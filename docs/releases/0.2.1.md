# AgentSpace 0.2.1

This patch corrects the macOS package from 0.2.0. The earlier archive did not
have a complete app-bundle signature, so Gatekeeper could report that
**AgentSpace is damaged and cannot be opened** after a browser added quarantine.
Mac users should replace that download with 0.2.1.

The application features and data format are unchanged. Existing spaces, runs,
agents, settings and saved keys remain compatible.

## Downloads and installation

- **Windows x64:** download `AgentSpace_0.2.1_x64-setup.exe` and run it. The
  installer is per-user and needs no administrator rights. If SmartScreen shows
  **Windows protected your PC**, select **More info**, then **Run anyway** for
  the project download you intended to use.
- **macOS, Apple Silicon:** download
  `AgentSpace_0.2.1_aarch64-apple-darwin.app.zip`, unzip it, move
  **AgentSpace.app** into **Applications**, and open it. Intel Macs are not
  supported by this release.

The Mac app now has a complete ad-hoc signature. It does not have a trusted
Developer ID signature and has not been notarized, so macOS can still require
an explicit exception. After trying to open the app once, open
**System Settings > Privacy & Security**, choose **Open Anyway**, and confirm
**Open**. Apple's
[instructions for opening an app from an unidentified developer](https://support.apple.com/en-us/102445)
show the same flow.

If the option is unavailable, this scoped fallback removes quarantine from the
copy in Applications:

```console
xattr -dr com.apple.quarantine /Applications/AgentSpace.app
```

On an update, macOS may ask whether AgentSpace can access a key it previously
saved in the login keychain. Enter your Mac login password if requested, then
choose **Allow** or **Always Allow** to let the app read the saved API key.

## Packaging correction

- Tauri now ad-hoc signs the sidecar, desktop executable and complete app
  bundle before the archive is created.
- Hardened runtime remains disabled. Enabling it while re-signing the
  PyInstaller one-file sidecar prevents its extracted Python library from
  loading under the same code identity.
- The release check now runs `codesign --verify --deep --strict` against the
  extracted archive, compares executable content without signature bytes, and
  launches the extracted sidecar with Python removed from its environment.
