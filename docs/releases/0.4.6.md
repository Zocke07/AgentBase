# AgentBase 0.4.6

The project is renamed from AgentSpace to AgentBase: the product, the backend
package, the Rust crate, the Tauri bundle identifier, the npm packages, the
generated schemas, environment variables and CI artifact names all carry the
new name, and so does every current document. The release adds no database
migration and changes no behavior beyond the identifiers themselves and the
one-time migration described below. See the [0.4.5](0.4.5.md) notes for the
visualization workspace, still current here.

## What changed

- **New identifiers everywhere current code runs.** The backend package
  (`agentbase`), its database filename (`agentbase.sqlite3`), the Tauri
  bundle (`dev.agentbase.desktop`), the Rust crate (`agentbase-desktop`), the
  npm packages (`@agentbase/desktop`, `@agentbase/schemas`), the dev data
  directory variable (`AGENTBASE_DATA_DIR`), the sidecar binary
  (`agentbase-sidecar-*`) and the CI artifact and workflow names all changed
  together; `test_every_release_version_identifies_the_same_build` and the
  hygiene tests keep them in lockstep with each release.
- **A pre-rename install is adopted once.** On its first canonical launch, an
  empty AgentBase app-data directory adopts a preceding AgentSpace profile
  wholesale, including its SQLite database (renamed in place, WAL and SHM
  companions included) without overwriting an existing AgentBase profile.
  This only touches the default OS app-data location; a dev override or a
  separate data directory is left alone.
- **Legacy values stay readable, never written.** The Windows Credential
  Manager / macOS Keychain entry, a browser's stored theme, selected space,
  panel sizes and folded-sidebar flags, and a saved `.viz.json` or
  `.dashboard.json`'s `agentspace://` schema URI all still read through to
  their AgentSpace-era value when no AgentBase value exists yet; every write
  uses only the AgentBase name from then on.
- **This is not an in-place upgrade.** The new bundle identifier makes
  Windows and macOS treat AgentBase as a distinct app from AgentSpace: it
  gets its own **Apps & features** entry and its own `AgentBase.app`. The old
  install is left running and untouched; remove it yourself once you have
  confirmed your data carried over.
- Historical documents (past release notes, the pre-rename session record)
  keep their original AgentSpace-era names and artifact names, since that is
  what was actually true when they were written.

## Downloads and installation

- **Windows x64:** download `AgentBase_0.4.6_x64-setup.exe` and run it.
  Installation is per-user and needs no administrator rights. The unsigned
  installer may show SmartScreen's **Windows protected your PC** prompt:
  select **More info**, then **Run anyway**. The installer includes the
  WebView2 bootstrapper.
- **macOS, Apple Silicon:** download `AgentBase_0.4.6_aarch64.dmg`, open it,
  drag **AgentBase** onto the **Applications** link, eject the image and open
  the app from Applications. If a copy from an earlier release is still in
  Downloads, delete it. An Intel Mac download is not included. No Python,
  Node or Rust installation is needed.

## macOS first launch and keychain access

The app has a complete ad-hoc signature but no trusted Developer ID signature,
and it has not been notarized. After trying to open it, macOS may block it. If
you trust this download, open **System Settings > Privacy & Security**, choose
**Open Anyway**, then confirm **Open**. See Apple's
[instructions for opening an app from an unidentified developer](https://support.apple.com/en-us/102445).

If that option is unavailable, the terminal fallback removes quarantine from
this app only, after you have placed it in Applications:

```console
xattr -dr com.apple.quarantine /Applications/AgentBase.app
```

On first launch after installing from a prior AgentSpace app, macOS may ask
whether AgentBase can access a key saved in the login keychain under the old
`dev.agentspace.desktop` service; this is the one-time legacy read-through
described above. Enter your Mac login password if requested, and choose
**Allow** or **Always Allow**. Keys stay in the OS keychain and are passed to
the local backend over stdin.

## Upgrade notes

Keep the AgentSpace app closed during AgentBase's first launch, so the data
adoption sees a quiet database. AgentBase installs alongside AgentSpace
rather than replacing it; once you have confirmed your spaces, agent
definitions and history are present in AgentBase, quit and uninstall (or
delete, on macOS) the old app yourself. A saved API key, Discord token,
theme, selected space and saved visualization all carry over automatically
on first read; nothing needs re-entering unless you choose to change it. The
API remains bound to `127.0.0.1`; the only network use beyond your chosen
model provider is the one-time runtime download from `files.pythonhosted.org`
when ChatGPT sign-in is first used.
