# AgentSpace 0.4.3

Four things found in the first day on 0.4.2: a space that inherited the
provider kept a model of the old provider when the provider changed, the
`news-scanner` could not read its own configuration, folders in the
Knowledge tree could not be deleted, and the sidebar could not be hidden.
The database gains migration 013 (the scanner's `read_file`); `/settings`
gains a side effect on the spaces and `/spaces/{id}/knowledge/folder` is new;
the event contract, the sandbox and the budget ledger are unchanged. See the
[0.4.2](0.4.2.md) notes for the model on each space, still current here.

## What changed

- **A provider change moves the spaces with it.** A space that inherits the
  provider now takes the new provider's default model when the app-wide
  provider changes, so the header never shows a pair such as "openai ·
  claude-haiku-4-5" that no provider can run. A space with a provider of its
  own is left alone; a space moved to Ollama has its model cleared until one
  is typed. The space page's provider list picks the same default.
- **news-scanner reads its configuration.** It shipped with `http_get` and
  `write_file` only and so tried to fetch `config/watchlist.json` from the
  web; it now has `read_file` like the other collectors. Put
  `config/watchlist.json`, `config/sources.json` and `config/limits.json` in
  the space folder (**Space settings → Open folder**) before the first run;
  the [user guide](../user_guide/3_agents.md) says what each holds.
- **Delete a folder.** The ✕ beside a folder in the Knowledge tree asks
  first, then removes the folder and everything in it, after copying every
  file it held under `.agentspace/backups/`. Links into it become unresolved
  links; the vault root and hidden folders are refused.
- **Hide the sidebar.** The button beneath Settings, or Ctrl/Cmd+B, folds the
  rail to icons with the names in tooltips and the space's initial in place
  of its name. Remembered per window.
- The "built-in" badge on Home's agent cards no longer wraps mid-word.

## Downloads and installation

- **Windows x64:** download `AgentSpace_0.4.3_x64-setup.exe` and run it.
  Installation is per-user and needs no administrator rights. The unsigned
  installer may show SmartScreen's **Windows protected your PC** prompt:
  select **More info**, then **Run anyway**. The installer includes the
  WebView2 bootstrapper.
- **macOS, Apple Silicon:** download `AgentSpace_0.4.3_aarch64.dmg`, open
  it, drag **AgentSpace** onto the **Applications** link, eject the image and
  open the app from Applications. If a copy from an earlier release is still
  in Downloads, delete it. An Intel Mac download is not included. No Python,
  Node or Rust installation is needed.

## macOS first launch and keychain access

The app has a complete ad-hoc signature but no trusted Developer ID signature,
and it has not been notarized. After trying to open it, macOS may block it. If
you trust this download, open **System Settings > Privacy & Security**, choose
**Open Anyway**, then confirm **Open**. See Apple's
[instructions for opening an app from an unidentified developer](https://support.apple.com/en-us/102445).

If that option is unavailable, the terminal fallback removes quarantine from
this app only, after you have placed it in Applications:

```console
xattr -dr com.apple.quarantine /Applications/AgentSpace.app
```

On an update, macOS may ask whether AgentSpace can access a key it previously
saved in the login keychain. Enter your Mac login password if requested, and
choose **Allow** or **Always Allow** to let the app read your saved API key.
Ad-hoc signed builds can prompt again when their code identity changes. Keys
stay in the OS keychain and are passed to the local backend over stdin.

## Upgrade notes

Quit AgentSpace before replacing the app. The existing database, spaces,
files and a fetched ChatGPT runtime are preserved in the application data
directory; the first launch applies migration 013 to it. If you changed the
app-wide provider on 0.4.2 and a space still names a model of the old
provider, changing the provider once more (or the space's model) sets it
right; from now on that happens on its own. The API remains bound to
`127.0.0.1`; the only network use beyond your chosen model provider is the
one-time runtime download from `files.pythonhosted.org` when ChatGPT sign-in
is first used.
