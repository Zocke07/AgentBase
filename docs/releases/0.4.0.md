# AgentSpace 0.4.0

Scheduled runs, a Usage section, a first-run tour, and fixes to two layouts
found in a real window. The database gains migration 009 (a `schedules`
table) and the local API gains `/schedules` and `/usage`; the event contract,
the sandbox and the budget ledger are unchanged. See the [0.3.3](0.3.3.md)
notes for the run canvas and the vault, still current here.

## What changed

- **A space can run a goal on its own at set times.** **Space settings →
  Schedules** takes a name, a goal, and when: every day or on chosen days at
  a time of day, or every few hours. The editor shows the app's own reading
  of the choice and the next three times before you save. A scheduled run is
  an ordinary run in every other way and is marked **from schedule** in Runs.
  AgentSpace has to be open for a time to fire; each schedule says what
  happens to a time that passes while the app is closed, run once at the next
  launch or skipped, and either way the following time is computed from the
  clock, so a laptop shut for a week runs it once, not seven times. The
  section says up front what the space's approval policy means for a run
  with nobody at the window.
- **Usage.** A new section, Ctrl/Cmd+5, with a month of model calls from the
  ledger the monthly cap is enforced on: spend against the cap, calls, input
  and output tokens, a bar per day, tables by model and by space, and the
  costliest runs with each run's peak and mean context (the input tokens of
  its calls). A run's inspector now shows each agent's own calls, tokens,
  cost, and the context it carried last and at most.
- **A first-run tour and an About box.** A fresh install opens a short tour
  that points at the parts of the window and ends on the demo run; Esc skips
  it. **Settings → About AgentSpace** shows the version that is running and
  the data folder, with **Open folder** and **Replay the tour**.
- **A run's memory within reach.** Under the supervisor's account, the memory
  the run wrote shows its status; **Approve** decides it there and **Open in
  the inbox** opens it beside the Knowledge inbox. A long account starts
  folded so the canvas and log stay in view.
- **Fixes.** With a second space, the Agents editor's move-or-copy bar stood
  beside the editor as a tall empty box and pushed the editor past the
  window's edge; it now sits above the editor, and the tools list is cut short
  instead of overflowing. On the canvas, tool chips lost their first letters,
  the Outcome title lost to its status pill, and handoff labels overlapped
  the cards; chips now show short verbs with a "+n" for the rest, and the
  cards and gaps are sized so titles and labels fit.

## Downloads and installation

- **Windows x64:** download `AgentSpace_0.4.0_x64-setup.exe` and run it.
  Installation is per-user and needs no administrator rights. The unsigned
  installer may show SmartScreen's **Windows protected your PC** prompt:
  select **More info**, then **Run anyway**. The installer includes the
  WebView2 bootstrapper.
- **macOS, Apple Silicon:** download `AgentSpace_0.4.0_aarch64.dmg`, open
  it, drag **AgentSpace** onto the **Applications** link, eject the image and
  open the app from Applications. If a copy from an earlier release is still
  in Downloads, delete it. An Intel Mac download is not included. No Python,
  Node or Rust installation is needed.

## macOS first launch and keychain access

The app has a complete ad-hoc signature but no trusted Developer ID signature,
and it has not been notarized. After trying to open it, macOS may block it. If
you trust this download, open **System Settings > Privacy & Security**, choose
**Open Anyway**, then confirm **Open**. See Apple's
[instructions for opening an app from an unidentified developer](https://support.apple.com/en-us/102445).

If that option is unavailable, the terminal fallback removes quarantine from
this app only, after you have placed it in Applications:

```console
xattr -dr com.apple.quarantine /Applications/AgentSpace.app
```

On an update, macOS may ask whether AgentSpace can access a key it previously
saved in the login keychain. Enter your Mac login password if requested, and
choose **Allow** or **Always Allow** to let the app read your saved API key.
Ad-hoc signed builds can prompt again when their code identity changes. Keys
stay in the OS keychain and are passed to the local backend over stdin.

## Upgrade notes

Quit AgentSpace before replacing the app. The existing database, spaces,
files and a fetched ChatGPT runtime are preserved in the application data
directory. The API remains bound to `127.0.0.1`; the only network use beyond
your chosen model provider is the one-time runtime download from
`files.pythonhosted.org` when ChatGPT sign-in is first used.
