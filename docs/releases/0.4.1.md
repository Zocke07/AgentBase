# AgentSpace 0.4.1

An investment research roster in the default space, answers per tool for the
approval gate, a yes that holds for a run, resizable panels and clearer labels
in Runs, and an Obsidian button that appears only where Obsidian is. The
database gains migrations 010 (the roster) and 011 (per-tool answers on
spaces, an approval's scope); the local API's `/settings`, `/spaces` and
`/approvals` gain fields; the event contract, the sandbox and the budget
ledger are unchanged. See the [0.4.0](0.4.0.md) notes for schedules, Usage
and the tour, still current here.

## What changed

- **The default space ships an investment research pipeline.** Ten
  built-in agents replace the three generic roles in **Main**: four Haiku
  collectors (`news-scanner`, `market-movers`, `event-calendar`,
  `portfolio-review`), the Sonnet `research-librarian`, `bull-architect`,
  `bear-architect`, `risk-manager` and `review-analyst`, and the Opus
  `decision` agent. Each names its own Anthropic model, so the cost shape
  does not depend on the app-wide default; none can run a shell command, and
  only the three collectors can fetch. They pass work to each other through
  files in the space folder and assume scripts and `config/*.json` files the
  app does not ship; the [user guide](../user_guide/3_agents.md) lists what
  to create first. On an upgrade, the shipped rows are added beside what you
  have; a generic role you edited stays and becomes deletable, an untouched
  one leaves the default space, and a name you already use is left alone.
  The generic three remain the **starter roles** a new space is seeded with.
- **Answers by tool.** Beneath the risk levels in **Settings → Limits and
  approvals**, every tool has one of three answers: **Ask, by risk level**
  (the default), **Always allow** or **Never allow**. An answer comes before
  the levels: a refused tool is refused without asking, and the agent is
  told the policy never allows it. A space can only make an answer stricter
  (**Space settings → Answers by tool**), and an agent whose definition names
  risk levels is still asked about an always-allowed tool outside them.
- **Allow for this run.** The approval panel's third button allows the call
  and every later call to that tool in the run, from any agent, whatever the
  arguments. Each later call is still recorded, **by your earlier answer**,
  and the panel's history marks the answer that started it **for the rest of
  the run**. A denial is still for the one call and its arguments.
- **Runs.** Handoff labels sit beside the card they go to, above the arrow,
  and a handoff back to the supervisor is labelled under the card it leaves,
  so no label is crossed by another arrow; hover over a label, a role, the
  goal or the outcome to read the whole text. Drag the edge between the run
  list and the run, between the canvas and the log, or the inspector's left
  edge, to size the panels; double-click puts one back. The sizes are
  remembered in this window.
- **Open in Obsidian** appears only when Obsidian is installed where its
  installer puts it. If opening still fails, the message says to add the
  folder from Obsidian's own vault picker rather than quoting the launcher.
- **Settings.** Changing the provider now selects that provider's first
  listed model instead of emptying the field.

## Downloads and installation

- **Windows x64:** download `AgentSpace_0.4.1_x64-setup.exe` and run it.
  Installation is per-user and needs no administrator rights. The unsigned
  installer may show SmartScreen's **Windows protected your PC** prompt:
  select **More info**, then **Run anyway**. The installer includes the
  WebView2 bootstrapper.
- **macOS, Apple Silicon:** download `AgentSpace_0.4.1_aarch64.dmg`, open
  it, drag **AgentSpace** onto the **Applications** link, eject the image and
  open the app from Applications. If a copy from an earlier release is still
  in Downloads, delete it. An Intel Mac download is not included. No Python,
  Node or Rust installation is needed.

## macOS first launch and keychain access

The app has a complete ad-hoc signature but no trusted Developer ID signature,
and it has not been notarized. After trying to open it, macOS may block it. If
you trust this download, open **System Settings > Privacy & Security**, choose
**Open Anyway**, then confirm **Open**. See Apple's
[instructions for opening an app from an unidentified developer](https://support.apple.com/en-us/102445).

If that option is unavailable, the terminal fallback removes quarantine from
this app only, after you have placed it in Applications:

```console
xattr -dr com.apple.quarantine /Applications/AgentSpace.app
```

On an update, macOS may ask whether AgentSpace can access a key it previously
saved in the login keychain. Enter your Mac login password if requested, and
choose **Allow** or **Always Allow** to let the app read your saved API key.
Ad-hoc signed builds can prompt again when their code identity changes. Keys
stay in the OS keychain and are passed to the local backend over stdin.

## Upgrade notes

Quit AgentSpace before replacing the app. The existing database, spaces,
files and a fetched ChatGPT runtime are preserved in the application data
directory; the first launch applies migrations 010 and 011 to it. The
investment agents need an Anthropic key; on another provider, change each
agent's model in its editor. Nothing runs unattended until you tick a risk
level or set a tool to **Always allow**. The API remains bound to
`127.0.0.1`; the only network use beyond your chosen model provider is the
one-time runtime download from `files.pythonhosted.org` when ChatGPT sign-in
is first used.
