# AgentSpace 0.4.2

The model moves from Settings to each space, the run list narrows by where a
run came from, a schedule can carry its own time limit beside a plain
readout of what an unattended run will do, and the Runs view gains a handle
on the summary and a real full-screen canvas. The database gains migration
012 (every space's model filled in; a schedule's time limit); `/settings`,
`/spaces`, `/schedules` and `/runs` gain or change fields; the event
contract, the sandbox and the budget ledger are unchanged. See the
[0.4.1](0.4.1.md) notes for the investment roster and answers by tool, still
current here.

## What changed

- **Settings chooses the provider; each space chooses its model.** The
  Model section in Settings is now **Provider**: whose models runs use, and
  so which key. **Space settings → Model** names the model that space's runs
  use, with no Inherit; a new space starts on the provider's default
  (`claude-opus-5` for Anthropic, `gpt-5.5` for OpenAI, typed for Ollama),
  and changing a space's provider brings that provider's first listed model.
  An agent can still pick its own. On upgrade, every existing space is given
  the model it was inheriting, so no run changes model that day.
- **Show, above the run list.** All runs, started by you, scheduled, or from
  Discord: one list narrowed by the sidecar, so pages stay whole.
- **Schedules say what an unattended run will do.** One paragraph at the top
  of the Schedules section reads out the risk levels a run there may call
  without asking, the tools always allowed or refused, what happens to
  everything else with nobody at the window, and where the run stops (steps
  per agent, agents per run, seconds). It turns amber while the space could
  do nothing on its own. A schedule can also set **Time limit for its
  runs**, so an overnight pipeline gets the hours it needs while runs you
  start by hand in the same space keep the space's limit.
- **Runs.** The supervisor's account has the same drag handle as the other
  panels, and scrolls once given a height instead of folding. The canvas's
  controls gain **Full screen**, which fills the window with the canvas and
  its inspector until Esc or the same button; the button beside it fits the
  run into view. The **Answers by tool** hint in Settings explains itself
  with an example.

## Downloads and installation

- **Windows x64:** download `AgentSpace_0.4.2_x64-setup.exe` and run it.
  Installation is per-user and needs no administrator rights. The unsigned
  installer may show SmartScreen's **Windows protected your PC** prompt:
  select **More info**, then **Run anyway**. The installer includes the
  WebView2 bootstrapper.
- **macOS, Apple Silicon:** download `AgentSpace_0.4.2_aarch64.dmg`, open
  it, drag **AgentSpace** onto the **Applications** link, eject the image and
  open the app from Applications. If a copy from an earlier release is still
  in Downloads, delete it. An Intel Mac download is not included. No Python,
  Node or Rust installation is needed.

## macOS first launch and keychain access

The app has a complete ad-hoc signature but no trusted Developer ID signature,
and it has not been notarized. After trying to open it, macOS may block it. If
you trust this download, open **System Settings > Privacy & Security**, choose
**Open Anyway**, then confirm **Open**. See Apple's
[instructions for opening an app from an unidentified developer](https://support.apple.com/en-us/102445).

If that option is unavailable, the terminal fallback removes quarantine from
this app only, after you have placed it in Applications:

```console
xattr -dr com.apple.quarantine /Applications/AgentSpace.app
```

On an update, macOS may ask whether AgentSpace can access a key it previously
saved in the login keychain. Enter your Mac login password if requested, and
choose **Allow** or **Always Allow** to let the app read your saved API key.
Ad-hoc signed builds can prompt again when their code identity changes. Keys
stay in the OS keychain and are passed to the local backend over stdin.

## Upgrade notes

Quit AgentSpace before replacing the app. The existing database, spaces,
files and a fetched ChatGPT runtime are preserved in the application data
directory; the first launch applies migration 012 to it. If you had chosen a
model in Settings, each space now shows it as its own under **Space settings
→ Model**; change it there from now on. The API remains bound to
`127.0.0.1`; the only network use beyond your chosen model provider is the
one-time runtime download from `files.pythonhosted.org` when ChatGPT sign-in
is first used.
